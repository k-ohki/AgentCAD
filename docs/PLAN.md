# 開発計画・進め方

最終更新: 2026-11-14（F2・F3・U1〜U3・V1・T は利用者 PC で確認済み。W も確認済み。D53・D54 も確認済み。D55・D56 も確認済み。D57 穴ウィザードは実カーネルで確認済み。D58 スイープ・D59 構造の整理も実カーネルで確認済み（9/9）。D60 図面は確認待ち）

## 1. 目的
機械系 3D CAD の中核機能（スケッチ拘束ソルバ、フィーチャーツリー、アセンブリ合致）を自前で実装する。
形状演算（BRep）は外部カーネルに任せ、差し替え可能にする。利用者は自分のみ・ローカル実行。

## 2. 構成（概要。詳細は SPEC.md）
- バックエンド: Python（全ロジック）。`core/`
- フロント: Web UI（Three.js）。開発中はブラウザで直接開き、最後に Tauri で包む
- カーネル: usd-brep（第一候補）/ OCCT（保険）。`cad.kernel.Kernel` の裏に置く
- 保存: USD（フィーチャー定義 + BRep + 表示メッシュ）

## 3. 進め方の原則
1. **core 先行・テストで完成させる**: 機能はまず UI 無しで `core/` に実装し、pytest で確認する。
2. **実測で判断する**: 性能・頑健性は推測せず測る。`scripts/bench_solver.py` と
   `tests/test_sketch.py::test_performance_budget`（400 変数でドラッグ 100ms 以内）を基準にする。
3. **縦切りで進める**: API だけ・UI だけを先に作り込まない。「スケッチを描く → 押し出す → 画面に出る」
   のように、端から端まで動く最小の機能を 1 本ずつ通す。API は、それを使う UI と同時に作る。
4. **ブラウザ先行、Tauri は最後**: UI は普通の Web アプリとして作り、Python サーバに WebSocket で
   つなぐ。Tauri は「Python を起動してウィンドウを出す殻」だけにして最後に足す（Rust を最小にする）。
5. **カーネルは適合テストで受け入れる**: アダプタを書いたら `tests/test_kernel_conformance.py` を通す。
   通れば上位層はそのまま動く。usd-brep で通せない項目があればカーネルを OCCT にする（D3）。
6. **この開発環境でできないこと**: ここには実カーネルも Tauri も入れられない。実機が必要な確認
   （フェーズ0、適合テスト、UI の目視）は利用者の PC で行う。デスクトップアプリからこのチャットを
   開けば、こちらから直接その PC 上で実行できる。
7. **git**: 1 論点 1 コミット。仕様や判断が変わるときは同じコミットで docs/ を更新する。

## 4. レビュー結果（2026-11-11）
既存コードを実測して見つけた問題と対応。

| 問題 | 実測（旧） | 対応 | 実測（新） |
|---|---|---|---|
| ソルバが遅い（密行列・拘束ごとの差分ヤコビアン・拘束ごとにランク計算） | 400 変数: 求解 1.9s / 診断 7.2s / ドラッグ 6.7s | バッチ自動微分 + 疎行列 LM + 1 パス診断に作り直し | 求解 6ms / 診断 26ms / ドラッグ 6ms |
| 定義状態の誤判定（距離 0 の寸法） | 矩形 20 個で「自由度 3・過剰定義」 | `abs()` をやめ、向きを符号として保持 | 自由度 0・完全定義 |
| 定義状態の誤判定（端点での正接） | 長穴で「自由度 4・過剰定義」 | 端点が円上にあるときは「半径方向 ⟂ 線」で定式化 | 自由度 0・完全定義 |
| ドラッグが 2 経路の場当たり実装 | — | 重み付き最小ノルム解に一本化 | — |
| 合致の向き（aligned）が効いていなかった | 残差に向きが入っておらず、初期姿勢に近い側へ収束するだけ | 面同士の合致は事前位置合わせ + 求解後に確認（flipped） | どの初期姿勢でも指定どおり |
| 平面-軸の一致が「軸の 1 点が平面上」だけだった | 残差が 1 つ（自由度 1 しか減らない） | 軸が平面内に寝る（自由度 2） | — |
| 不正な参照・合致が求解時まで分からない | 例外が求解中に出る | 作成時に型を検査 | — |
| 参照の解決が各所に散らばっていた | — | `TopoNames.find_face/find_edge` に集約。救済と候補提示 | — |
| Undo がパートとアセンブリで重複 | — | `cad.doc.History` に共通化 | — |
| カーネルの受け入れ条件が文章だけ | — | 適合テストを追加 | — |

計画面の見直し:
- 「API サーバ → UI」の順をやめ、原則 3・4（縦切り、ブラウザ先行）に変更。
- フェーズ0 を「API 一覧を出すスクリプト」から「適合テストを通す」作業に格上げ（原則 5）。

### 6.0 ファイルの読み込み・書き出し（2026-11-14 実装。D71）
STL・3MF・OBJ の書き出し（パート・アセンブリ、細かさ 3 段階、3MF・OBJ は部品ごと・色つき）と読み込み（参照用のボディのパート）。
STEP は対応しない（usd-brep に入出力が無く、曲面の定義も取り出せない）。
利用者の確認待ち: 実際のスライサ（PrusaSlicer・Bambu Studio など）と Blender で書き出したファイルを開けるか、手元の STL を開いたときの面の分かれ方。
残り（必要になったら）: glTF / GLB の書き出し、読み込み時の色、STEP の読み込み（OpenCascade を足す）

次の段階の候補（効果が大きいと思う順。2026-11-14 に利用者へ提案したものを含む）:
1. 操作の仕上げ
   - Enter / Esc を一般的な 3D CAD どおりどこでも効かせる（今は入力欄の中だけのパネルがある: 断面・スケッチのパターン）
   - スケッチの「作成中に寸法を入力」（線・円を描いた直後に長さ・直径を入れる）
   - ショートカットバー（S キー）・カーソルの近くのメニュー
   - フィーチャーツリーのドラッグ（順番の入れ替え・ロールバックバーの移動）
   - 未保存の変更があるときの終了確認（Tauri の殻）
2. 外観と表示
   - 部品・面の色（外観）。断面の切り口・アセンブリの見分けにも効く
   - 断面の設定の保存、図面の断面図（ハッチング）・詳細図・中心線
3. モデリングの拡張
   - スケッチ: スプライン、楕円、テキスト
   - フィーチャー: ロフト、抜き勾配、リブ（関数の振る舞いは調査スクリプトで確かめてから）
   - 設計テーブル（変数の組を切り替えるコンフィギュレーション）
4. アセンブリ
   - 合致の値に式、サブアセンブリ、アセンブリの図面
5. 土台
   - 命名の強化（G: 面分割時の `#n` の安定性を実カーネルで検証）
   - 性能: 残りの約 8 割はカーネルの中。さらに速くするには usd-brep に「面の追跡」か「三角形 → 面の番号」の出力が要る（D65）

## 7. バックログ（既知の課題）
- ソルバ: 診断は 1600 変数で約 2.5s（グラム・シュミットが密）。連結成分ごとの分割で改善できる
- ソルバ: 寸法を大きく変えたとき別の枝（裏返った形）に収束しうる。段階的に寸法を動かす継続法が未実装
- スケッチ: 距離 0 の点-点距離（勾配が 0）、円弧の向きの保持
- 命名: 面分割時の `#n` は sort_key（重心など）順。実カーネルでの検証が必要
- 合致: 角度 0°/180° は勾配が 0 になる（平行合致を使う）
